처음 일반 샌드박스에서 실행한 HTTP 테스트는 localhost 연결 자체가 `EACCES`로 차단됐습니다. 로컬 루프백 연결을 허용한 실행 환경에서 다시 실행해 통과했습니다. 어댑터 테스트는 주입한 가짜 fetch/ChannelProvider만 사용하며 실제 공급자 URL에 통신하지 않습니다.

## 자동 테스트가 확인한 내용

- 5개 필수 API의 Mock 응답, simulated/reviewRequired/sourceMissing 및 출처 없음.
- 직접 HTTP 요청으로 추가 학생 필드·메뉴 값의 학생 객체·자유 prompt 필드·소수 집계·등록되지 않은 주제 ID를 제출하면 400 및 업스트림 호출 0회입니다. 메뉴 문자열 자체는 내용으로 차단하지 않습니다.
- 인증 누락/오류, Origin/Host, JSON 타입/크기/구문, 상속 속성 topicId, 잘못된 월/숫자/중복 수신자.
- 승인 전/식단 변경 후 발송 차단, 버전 감소 방지, 새 버전 정정 및 correctionNeeded.
- 동일 배치 동시 발송, 동시 재시도, 재시작 후 중복 409, 동일 버전 다른 템플릿 중복 차단.
- upsert 실패의 부분 재시도와 최대 3회, 시도 이력, 불명확 이벤트 재시도 차단.
- 별도 자식 프로세스 강제 종료 후 reserved/upsert/event 각각의 복구. 이벤트 전 실패만 재시도 가능.
- 상태 프로세스 독점 잠금, 손상 JSON/잘못된 버전/비객체 구조 시작 차단, 저장 실패 시 외부 호출 0회.
- 전화번호 원문/로컬 토큰 미저장, 공개 상태에 HMAC 없음, 감사 로그에 민감 본문 없음.
- Liner 요청 경로/헤더/모델/필드, UTF-8 청크 경계·SSE CRLF·댓글·출처, HTTP 200 data-error, 스트림 잘림, 오류 JSON·401·429·500·오프라인·타임아웃·초대형 응답.
- Search SSE의 단독 CR 줄바꿈과 추가 메타데이터 이벤트, 빈 출처 제목의 호스트명 대체, 출처 배열·delta 타입 오류, 불완전한 종료, 본문 없는 감사 진단.
- 관측된 `isScholarlyQuery` 전용 이벤트 다음에 출처 배열 이벤트가 오는 경우 정상 처리. 이 예외가 잘못된 출처 자료형이나 알 수 없는 출처 객체를 허용하지 않는지 검증.
- AI 캐시/동시 질의 병합, 초당 2회 미만 호출 시작, 오류 미캐시, 비밀정보 echo 차단.
- Liner 대기열 만료 시 공급자 호출 없이 504 반환, JSON에서 이스케이프되는 자격 증명의 응답 본문·인용 제목 노출 차단.
- Router 30초·Search Agent 60초 기본값과 각 경로의 만료 처리를 짧은 주입 값으로 확인.
- 목록에 없는 메뉴와 200자 경곗값이 두 AI 경로에서 사용되며, 공백·전각 문자·특수문자·알레르기 번호가 모의 공급자 요청에서 보존됩니다. 빈 값·문자열이 아닌 값·201자 값은 호출 전에 거부합니다.
- 자동 재시도 3회 소진 후 발송 응답과 배치 조회에서 `retryable:false`, 추가 요청은 409.
- Channel Talk 최소 payload·/open/v5 경로·auth·event 응답 검사, 명시적 live opt-in 없이 실제 호출 차단.
- 수동 txt/csv 생성과 기록, 재시작 후 manual 유지, requested/uncertain 대상 자동·수동 재발송 차단.

메뉴 이름을 담는 텍스트 필드의 개인정보 잔여 위험과 v0.3과의 차이는 [구현 근거](IMPLEMENTATION_NOTES.md)에 기록했습니다.

## MVP 검증 범위

학생 객체와 임의 필드 차단, 인증, 최신 S2 승인, 발송 중복 방지 및 요청·도착 상태 구분을 필수로 유지했습니다. 메뉴 문자열 정규식 차단을 검사하던 사례는 새 정책의 경계값과 원문 보존 검사로 교체했습니다. 오류 미캐시 재호출 검증은 대표 429 사례에 적용하고, 401·500은 오류 코드 매핑을 확인합니다.

대규모 부하, 장시간 안정성, 극단적인 장애 복구, 클라우드 다중 서버 검증은 이번 범위에서 제외했습니다. 기존 로컬 재시작 및 짧은 강제 종료 검사는 유지했습니다.
